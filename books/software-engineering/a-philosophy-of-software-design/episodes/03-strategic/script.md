# 第 3 集：能工作的代码是不够的——战略式 vs 战术式编程

大家好，欢迎回到《软件设计的哲学》有声博客。今天第三章：能工作的代码是不够的。钩子先放这儿：如果你团队里有人改需求特别快，大家喊他英雄，但接手他代码的人都在骂——那很可能不是个人能力问题，而是思维方式问题。[pause]

作者把常见思维叫「战术式编程」：主要焦点是尽快让某功能或某次修 bug 能跑起来。乍看完全合理——还有什么比能工作的代码更重要？问题在于短视。你赶工期，不想为未来多想；不花时间找最佳设计，只想尽快能跑。你告诉自己：多一点点复杂性、一两处蹩脚实现，只要当前任务更快完成，就没什么大不了。

可复杂性是增量产生的。不是某一件事毁掉系统，而是几十、几百个小妥协堆起来。每个人、每次任务都用战术思维，复杂性就迅速累积。很快这些复杂性开始找麻烦，你开始后悔早年的捷径；但你又告诉自己：让下一个功能跑起来，比回去重构更要紧。于是再打补丁，补丁再制造复杂性，代码变成一团糟。清理要几个月，日程容不下，于是继续战术。一旦走上这条路，就很难拐回来。[pause]

书里还点名一种极端人物：战术龙卷风。产出极快、完全战术。紧急功能他最快，管理层有时当英雄。但留下毁灭痕迹；真正要长期维护的工程师，很少觉得他是英雄。清理混乱的人，才是真正的英雄，进度却显得更慢。

成为好设计师的第一步，是意识到：能工作的代码是不够的。为了更快完成当前任务而引入不必要的复杂性，不可接受。最重要的是系统的长期结构。多数代码是在扩展现有库，所以最重要的工作是促进将来的扩展。代码当然必须能工作，但「能工作」不该是主要目标；主要目标应是产出出色设计，并且这设计也能很好地工作。这就是战略式编程。[pause]

战略式需要投资心态：花时间改进设计，而不是永远走最快捷径。短期会慢一点，长期会更快。主动投资例如：给每个新类找简单设计，多试几种方案选最简洁的；设想将来可能怎么改，让这些改动更容易；写好文档。被动投资则是：设计错误难免会暴露；发现了别忽略、别只打补丁，花点额外时间真正修好。战略式是持续做小幅设计改进；战术式是持续往系统里塞将来会惹麻烦的复杂性。

该投多少？一次性把整个系统设计完——瀑布——我们知道不行。理想设计随理解加深逐渐涌现。更好的是连续做大量小额投资。作者建议把总开发时间的百分之十到二十用于投资：小到不严重冲击日程，又大到随时间产生重大收益。初始项目会比纯战术多花一到两成时间；几个月内你会开始感到好处，不久开发速度至少比战术快一到两成，到那时投资几乎「免费」——过去的收益足够支付未来的投入。反过来，战术初期可能快一到两成，但复杂性很快把速度拖下去，省下的时间很快吐回去，整个生命周期更慢。质量很差的代码库，开发速度至少慢两成——有经验的人会告诉你这不是夸张。[pause]

书里有一张示意曲线：战术一开始爬得更快，但复杂性积累更快，生产率下降；战略曲线稍后追上并反超。作者强调这只是定性示意，没有精确实证形状。他还提到「技术债」：战术是从未来借时间，现在快、以后慢；像金融债一样，偿还往往超过借入。不同的是，多数技术债永远还不清，你会一直付利息。交叉点大概在多久？他个人估计大约六到十八个月，多半和记忆有关：几个月后写代码时的想法忘了，复杂代码会显著拖慢速度。这是个人意见，没有硬数据。

初创公司常有强大力量反对战略式：尽快发早期版本的压力下，一到两成投资都像负担不起。很多人赌：成功了再雇人清理。但代码库一旦变成意大利面，几乎修不好，你会在整个产品生命周期付高昂开发成本；好设计或坏设计的回报来得也很快，战术甚至未必能加快首次发布。另一点：公司成功很依赖工程师素质；最好的工程师在意良好设计。代码库很糟，消息总会传出去，招聘变难，最后只能用更普通的人，成本更高，结构继续退化。[pause]

书里举例：Facebook 早年座右铭是「快速行动，不怕犯错」，鼓励新人很快往生产提交。赋能感强，但代码库受了伤：不稳定、难懂、少注释少测试。后来改成「在坚实的基础架构上快速行动」，鼓励更多设计投资；能否清掉多年战术积累，仍待观察。作者也说，Facebook 未必比一般初创差很多，只是特别显眼。相对地，差不多同期成长的 Google 和 VMware 更偏战略，重视高质量代码与良好设计，技术文化在硅谷口碑很好。两种路线公司都可能成功，但在关心设计、代码整洁的公司里工作，会有趣得多。

结论：好设计不是免费的，必须持续投资，小问题才不会堆成大问题。好设计最终会收回成本，而且往往比你想的早。关键是始终如一地把投资当作今天要做的事，而不是「等危机过后再清理」。危机一个接一个，一推迟就容易永久战术化；等得越久，问题越大，越吓人，越容易再推迟。最有效的是：每位工程师持续做小额设计投资。

带走三句话：能工作不够，长期结构才是主目标；花百分之十到二十做战略投资，通常划算；别等「以后再清理」——以后很少真的到来。下一集我们继续往后续章节走。我们下集见。
